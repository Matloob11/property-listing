# Property Listing New — parity with the old desk (14 Sep 2026)

Everything the old Property Listing app (Bitrix app 46, youtupia.com) offers is now on the new desk
(app 81). Extras that only the new desk had were kept.

## Desk (listing table)

- **Bulk Options** menu next to the status tabs, same 15 items and order as the old desk:
  Transfer to Agent, Transfer Owner, Transfer (between portal accounts), Refresh Listings,
  Duplicate Listings, Delete, Publish, Publish To Bayut, Publish To Dubizzle, Publish To PF,
  Unpublish, Unpublish From Property Finder, Unpublish From Bayut, Unpublish From Dubizzle,
  Push to Website. Plus **Import from old desk (CSV)**.
- Admin-only items are enforced the same way as the old desk (publish/unpublish/refresh/transfer
  between accounts/delete). Non-admins see them greyed with an "admin" tag.
- **Download CSV (Beta)** is always visible (not only after selecting rows).
- Filters gained **Sub community** and **Project status**; Developer is a dropdown; Portal list
  includes Property Finder API.
- Column renamed to **Expiry Date From Portals**. Sort direction shows an arrow instead of "A"/"Z".
- Infographics legend now has **JE** like the old desk.
- Row menu gained **Edit listing** and **Delete** (admin).
- View Details shows Listing views, days listed, furnished, parking and a link to the public page.

## Create / edit wizard (7 steps, same names as old)

1. **Property Details**: bedrooms (Studio–20) and bathrooms (0–20) dropdowns, Fireplace,
   Ownership (Free Hold / None Hold / Lease Hold / GCC), Rental period, Sale price + Hide price +
   Down payment for sale listings, **per-portal pricing** (Property Finder block and Bayut block),
   payment method incl. Cash,Installments, cheques 1–12, financial status Mortgaged/Cash,
   private vs commercial amenity lists, Arabic title/description, Listing Agent / Owner / Landlord
   with **+ Add** dialogs (name, email, phone, BRN, role), per-portal agents (Website, Bayut, PF API),
   owner role Admin/Staff, **Enable NON-ADREC**, Rera / DTCM permit tabs, DTCM permit number.
   Side panels: Draft Property, **Verification** (checklist), **Available Upgrades**,
   **Listing Insights** and **History** (Date / Created By / New Value).
2. **Media**: photos with watermark, YouTube link, Video link, QR code link, more videos, floor plans.
3. **Location**: location text ("City - Community - Sub Community - Building") with Add Location,
   city/community/sub community/building, latitude/longitude with **Pin My Location**,
   **Bayut Location** block (copy from system location).
4. **Publishing**: all portals (Property Finder, Bayut, Dubizzle, JE, TRB, Simsari, Sudonum,
   Properstar, WWW Website, PF API, Rightmove), portal accounts, expiry date, View Insights.
5. **Notes**: Write a New Note (type + text + Add) with author and time, list of notes.
6. **Documents**: free "Add Documents" upload plus the fixed slots.
7. **Completed**: Publishing Status radio (Publish / Unpublish / Save as draft / Send for approval /
   Save as pocket listing) then Submit.
- Steps can be opened directly by clicking them (this did not work before).

## Server

- History log on every listing (create, every field change, bulk actions, refresh).
- Public page counts **Listing views**; `/api/listings/:id/insights`.
- Portal XML feeds at `/feeds/<portal>.xml` (pf, pf_api, bayut, dubizzle, houza, trb, simsari,
  sudonum, properstar, website, rightmove). Live listings switched on for a portal appear in its feed.
  Point each portal account at its feed URL; Bayut/Dubizzle use the Bayut location and Bayut prices.
- New endpoints: delete, bulk-delete, bulk-duplicate, bulk-refresh, bulk-portals, transfer-owner,
  transfer-account, notes, directory (agents/owners/landlords/accounts), import (CSV from old desk).
- Duplicate reference numbers are rejected on create.
- Exports and public page respect "Hide price".

## Deploy

`npm run build` then `bash deploy/deploy.sh` (backs up the live copy first, uploads, restarts).

## Contracts & e-signature (added 14 Sep 2026, evening)

- Row menu → **Tenancy Contract / e-sign** (rent listings) or **Sale Agreement / e-sign** (sale listings);
  also from View Details → "Contracts / e-sign". Opens the contract panel for that listing.
- Panel: New Tenancy Contract / New Sale Agreement (property, owner, agent and prices are filled from
  the listing), edit tenant/buyer, owner, property and terms, Save draft, Preview PDF,
  **Send for signature**, Cancel, Delete (admin), Activity log.
- Sending creates one secure link per signer (`/sign/<token>`, valid 30 days). Buttons: WhatsApp
  (opens wa.me with the message ready), Email (mailto), Copy link. The agent sends the link from
  their own WhatsApp/email.
- Signing page (no login, mobile friendly): contract summary, full PDF, name, draw or type the
  signature, consent checkbox. Records name, date/time, IP and browser. Re-opening a signed link
  shows the thank-you page; once everyone signed it offers the final PDF.
- When all parties sign: contract status **signed**, the signed PDF is attached to the listing's
  Documents (Ejari / Tenancy or Sale Agreement slot), the listing shows a "Tenancy: signed" chip and
  History gets an entry. PDF served at `/api/contracts/<id>/pdf` (login) or `/sign/<token>/pdf`.
- Server: `server/contracts.js` (templates + PDF), `server/pdf.js` (PDF writer with JPEG signatures),
  `server/signPage.js` (public pages), `contracts` table. Contract terms are standard Dubai tenancy /
  sale clauses; edit them in `server/contracts.js` if the legal team wants different wording.

## Tenancy Contract tool (clone of Bitrix /tenancy/, added 14 Sep 2026)

- Third collapsible bar on the desk, under Filters: **Tenancy Contract**. Same page as the Bitrix
  Sign → "TENANCY CONTRACT" button: hero text, Agent (you), stepper 1. Details / 2. Template / 3. Send.
- Step 1: Tenant (Bitrix CRM search: contact, company, lead → name/email/phone filled, "In Bitrix" /
  "Not in Bitrix" badge, duplicate hint), Owner (contact search), Property (Owner's Unit search fills
  property no, building, location, plot, size, owner details; extra: pick a listing from this desk),
  Rent (contract date → From, To = +1 year −1 day, contract value = rent, deposit = 5%, payment mode).
- Step 2: Unified Tenancy Contract (Ejari) template card.
- Step 3: summary with tenant/owner email boxes, WhatsApp tenant/owner (downloads the filled PDF and
  opens wa.me with the same message as Bitrix), Email tenant/owner (Gmail SMTP, same account as the
  Bitrix tool, PDF attached), Download PDF, WhatsApp both / Email both, Save to draft, Human review.
- PDF: `server/tenancyPdf.js` is a 1:1 port of the Bitrix PdfMaker (same coordinates, money words,
  terms page) using the same two Ejari template images (`server/assets/`).
- Board under the form (replaces the Bitrix Sign board): Draft / Under review / Sent / Partially
  signed / Signed, with PDF link, Open (reloads the form), stage move (Signed asks for the signed PDF
  upload), Delete (admin). The 14 existing Bitrix tenancy records and their PDFs were imported.
- Server: `/api/tenancy/*` (search, lookup, prepare, whatsapp, email, save, list, stage, download),
  `server/bitrixCrm.js` (REST with the user's portal token; the client refreshes the token through
  BX24.refreshAuth when it expires), `server/smtp.js`, table `tenancy`, files in `data/tenancy/`.
  SMTP settings live in the server `.env` (`TENANCY_SMTP_*`).
- CRM search/lookup goes through the Bitrix inbound webhook set in the server `.env` as
  `BITRIX_WEBHOOK` (currently the existing webhook "Inbound webhook", ID 73, owned by the desk admin,
  CRM scope). Without it the server falls back to the user's portal token, but local app 81 only has
  `user, user_brief, placement` scope, so CRM calls fail; the Bitrix developer pages on this on-prem
  portal do not render the "create webhook" cards, so a new dedicated webhook could not be created.

## Property Finder live data (15 Sep 2026)

- Server syncs the A7 Property Finder account through the Atlas API (`PF_API_KEY` / `PF_API_SECRET`
  in the server `.env`, every `PF_SYNC_MINUTES`, plus "Sync now" on Overview and
  `node server/scripts/pfSyncNow.js`). Demo data was removed; every listing on the desk is real.
- Listings: all 386 PF listings with title, description, type, beds/baths, size, plot, parking,
  furnishing, amenities, prices (sale or rent periods, cheques, down payment, price on request),
  photos, agent, PF location tree (city / community / sub community / building + coordinates),
  project status, PF state (live / taken down with reasons), publish date and PF quality score with
  its suggestions. Desk shows a "PF live · score" or "PF down" chip; View Details and the wizard show
  the full PF section.
- Leads: PF leads (WhatsApp, call, email) with sender, contact, listing, agent, status, call times
  and the PF reply link — new **Leads** section, per-listing leads in View Details, latest leads on
  Overview.
- Agents: PF users synced into the agent directory (name, email, phone, position, photo).
- Overview: totals, live on PF, average quality, leads today/week/month, PF credits and cycle, agents,
  latest leads, 14-day lead chart, listings by type, taken-down reasons, top listings and agents by
  leads, live listings with low quality score.
- Note: Node's default `Accept-Language: *` header makes the PF locations endpoint return 404; the
  client sends `Accept-Language: en`.
